# Agent 研究与实践沉淀

目标：把问题、源码机制、取舍和 Robin 的实际修改串起来，便于回忆与面试复盘。
在仓库根目录解析下文路径；本 skill 的模板位于 [references/note-template.md](references/note-template.md)。

## 工作流

1. 简短告知正在使用此 skill。先读 `knowledge/agent-design/README.md`，搜索相关主题；同一设计问题更新原篇，不因换参考项目或换对话而另建笔记。
2. 核实参考实现。目标仓库存在 `.codegraph/` 时先使用 CodeGraph，随后按需搜索。记录版本或 commit、文件、符号及关键行；可用时附固定版本的上游链接。本地修改版与官方版本分开说明。
3. 回答用户问题后，在本轮结束前按照模板整理研究。新篇文件名为 `YYYY-MM-DD-topic-slug.md`，日期使用当前会话时区，slug 使用小写英文与连字符；同名冲突先核查是否同题，仅不同主题追加简短限定词。
4. 将助手建议、用户选择、实际代码改动和验证结果分开。尚未决定也先落笔；后续用户选择或调整方案、要求实施、实现完成时，读取原篇再更新。不必重跑无变化的上游研究。
5. 同步索引的主题、参考项目、状态、更新日期。回答末尾简短链接本次笔记。不自动提交 Git。

## 证据与状态

- 初始状态为“研究中”（证据不足）或“待决定”（已形成候选方案）；有明确用户选择才标“已决定”，相关代码确已修改才标“已实现”，约定验证通过才标“已验证”。
- 总状态之外保留“用户最终决定”和“实现与验证”两节。实施请求可作为用户选择的证据，但不是实现完成的证据；生成总结也不是任务成功的证据。
- 区分“源码事实”“推断”“未核实”。负面结论限定检索范围，例如“在所检查的核心循环中未发现”，不声称整个生态都不存在。
- 重要决定被替换时添加日期、旧决定、新决定与理由；重新进入研究或待决定阶段时据实调整状态，保留以前的验证适用范围。
- 不编造用户理由、版本、测试、commit 或未见过的实现。版本未查明时明确标注。源码行号是阅读入口，改动后可能漂移，必须同时给出符号名称。
- 不复制大段上游源码，不保存密钥、完整 session 或敏感输出。故障现场只保留复现必要摘要和本地工件定位。
- 尊重用户手写内容，更新时保留其笔记和决策；没有代码改动时明确写“未实施”，不要为了填模板而修改运行时代码。
- 本机制不扩张工具权限。只读或规划模式不写入；说明待沉淀主题，恢复可写且相关任务继续时再更新。

## 触发边界示例

| 场景 | 行为 |
| --- | --- |
| “Pi 怎样裁剪历史？” | 查证实现，创建或更新历史裁剪主题 |
| “就采用刚才第二种方案” | 根据上下文更新原篇用户决定；有歧义时澄清，不猜选择 |
| “实现这个方案” | 记录已选方案，完成代码及验证后再更新对应状态 |
| “OpenCode 的 logo 很好看” | 不触发设计研究沉淀 |
| 上游证据暂时无法获取 | 记录来源限制，相关结论标为未核实 |
